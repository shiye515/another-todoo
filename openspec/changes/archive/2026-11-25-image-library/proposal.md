# Proposal

## Why

当前图片页只支持单张图片：每次"选择图片"都会覆盖上一张，应用重启后图片与处理结果完全丢失。实际使用中用户需要反复向同一台设备发送不同图片，每次都要重新选择、重新裁剪、重新量化，成本高。图片应作为带完整处理成果（成品 + 两个量化图）的资产持久化，并以列表形式集中管理、一键发送。

## What Changes

- 图片页重构为**纯列表布局**（无独立处理区）：每个条目展示缩略图、名称、添加日期，并带**量化图发送**、**抖动图发送**、**重新量化**三个按钮，以及删除按钮
- "选择图片"改为**"添加图片"**（⌘O，一次可选多张）：每张新图追加为独立条目，不覆盖已有条目
- **添加即裁剪**：添加的每张图片立即依次进入裁剪窗口，确认裁剪后以 528×792 成品图入库；**原图不保留**（仅存裁剪成品）；取消裁剪则跳过该张（不入库），队列继续下一张
- **量化图持久化**：入库时由成品图生成两个量化图（无抖动 / Floyd–Steinberg）并随条目持久化；发送直接使用持久化的量化图
- **重新量化**：每个条目提供"重新量化"按钮，从成品图重新生成两个量化图并覆盖持久化副本；量化图文件缺失时自动从成品图补建
- **处理结果随条目持久化**：裁剪成品、裁剪配置与量化图存储在条目中；重启后条目恢复，发送按钮立即可用，无需重做任何处理
- 条目发送走现有流程：持久化量化图编码 payload，弹出现有的发送进度窗口
- 支持删除列表条目（同时删除成品图、量化图与元数据）
- 移除量化预览三列展示与原"第 1 步：选择图片"占位流程

## Capabilities

### New Capabilities

- `image-library`: 图片库的积累、持久化与管理——多图添加互不覆盖、添加即裁剪入库（只存成品）、量化图随条目持久化并可重新量化、条目列表带逐条发送与删除、重启后立即可发

### Modified Capabilities

（无——仓库主规格库当前为空）

## Impact

- **新增**：`Models/LibraryImage.swift`（条目模型：元数据 + 裁剪配置）、`Services/ImageLibrary.swift`（库服务：存储/缓存/重新量化持久化）
- **重构**：`Views/ImageView.swift`（纯列表布局 + 行内按钮组）、`Services/ImageProcessor.swift`（添加裁剪队列；量化预览展示职责移除；保留 payload 编码与重新量化编排）
- **存储**：`~/Library/Application Support/TodooCardMacApp/ImageLibrary/`（每条目一个目录：成品 PNG + 两个量化 PNG + manifest.json）；原图不保留
- **移除**：量化预览三列 UI（`QuantizationView`）及相关缓存
- **不受影响**：传输服务、BLE 协议、设备页
